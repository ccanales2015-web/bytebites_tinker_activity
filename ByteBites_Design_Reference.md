# ByteBites Reference File

## About This Project
You are building the backend logic for a campus food ordering app called ByteBites
using Python classes and simple algorithms.

## Project Scope
Do not add authentication logic, a database layer, or any features not described 
in the spec.

## Behavioral Instructions
Keep the ByteBites design simple and appropriate for a beginner-level Python object-oriented programming exercise.

Follow the Client Feature Request closely. Do not invent features or requirements that are not specified.

Use exactly four core classes: Customer, FoodItem, Menu, and Transaction.

Give each class a clear, distinct responsibility and avoid unnecessary duplication.

Use basic Python classes and built-in data structures such as lists and dictionaries.

Do not introduce databases, web frameworks, APIs, authentication services, or additional architectural layers unless explicitly requested.

When generating UML diagrams, show each class's attributes, essential methods, and relationships in a clear, readable format.

Distinguish between requirements explicitly stated by the client and reasonable design assumptions.

Explain important design choices briefly so I can understand and verify them.

Do not generate implementation code until I request it.

If a proposed design conflicts with the feature request, identify the conflict rather than silently changing the requirements.
